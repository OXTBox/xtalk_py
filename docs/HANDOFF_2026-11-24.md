## Choices made (easy to change)
- Variables stay in a frame dictionary (as the interpreter), not Python locals: the unset-variable-is-its-own-name
  rule, globals and script locals come out right without analysis. Cost: no speed gain.
- `switch`: LiveCode falls through when a case has no break (asked it: LIVECODE_FACTS). The interpreter did
  not; fixed in parser (keeps where the default sits), interpreter and translator, 3 measured cases added
  to golden.json by hand (golden.py makes the same when run). The translator writes if/elif when every case
  ends in break (stacked cases merged), else a "start here, run on" form.

## Known limits
- The 20,591 handler figure means "turns into Python that compiles", not "proven to run like LiveCode":
  that proof is the golden set only (352 cases).
- `do "exit repeat"` (or next repeat) inside a translated loop is not caught (the loop is a Python loop).
- Objects, the message path, send/dispatch, properties beyond the in-memory host: Phase 2.
