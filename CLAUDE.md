# xtalk_py: notes for Claude Code

A Python runtime for xTalk (LiveCode Script), so the owner's LiveCode 9.6.3 scripts and
stacks keep running after 9.6.3. Read `docs/ROADMAP.md` first (decisions, phases, next step).

## Who

The owner wrote the original iGame3D (2007) and is fluent in LiveCode Script. Explain
Python-side work plainly. Summarise data in words and small tables; raw JSON dumps are
not useful to him.

## Decisions already made (do not reopen without the owner)

- Interpreter first; translator to Python maybe later.
- GUI: raylib + Dear ImGui, for the editors, the stack runtime and 3D alike.
- xt3d, Vibecode3D and LIB_LLM are separate tools in their own projects. They meet
  through shared formats (harvest JSON, 0/1 sprite frames, models, raylib-named calls).

## Working rules

- The reference for behaviour is LiveCode 9.6.3 itself, not documentation or memory.
  When unsure what LiveCode does, ask it: `~/projects/LIB_MCP/tools/lcmcp --standalone eval --server '<expr>'`,
  and record the answer in `docs/LIVECODE_FACTS.md`.
- `docs/GLOSSARY.md` and `docs/glossary.json` are generated by `tools/glossary_census.py`;
  re-run it instead of editing them. Mark progress in the interpreter's own test list,
  not in the generated file.
- Never edit the owner's other projects from here without being asked.
- Python 3.14 is installed in WSL; pip is not yet. Ask before installing packages.

## xTalk pitfalls already learned (from the owner's projects)

- Case-insensitive: a variable named `tExt` or `tHere` is the keyword `text` / `there`.
- A one-line `if c then x` directly before an `else` line takes that else.
- `does not begin with` is not xTalk: `not (x begins with y)`.
- An array element is either a value or an array; putting into `a[i]["k"]` replaces `a[i]`.
- Chunks nest small-inside-big only: `word 1 to -1 of char 1 to 5 of x` is a compile error, "bad chunk order".
