## The script corpus (`corpus/`)

All the owner's LiveCode scripts in one place: knowledge base and test bench. Read
`corpus/INDEX.md` (or `corpus/index.json`) to find examples. `corpus/sources.json` is the
catalogue (descriptions are written there); `tools/corpus_sync.py` refreshes the copies
of project scripts and rebuilds the indexes. `originals/` holds scripts that live only
here (GridDraw, the Bitmap Vector Tracer). New scripts arrive in the shared inbox `~/projects/LIB_LLMIN/xtalk_py/toCorpus/` (process in
its README: Spark's draft in its `_spark/` from `tools/spark_catalogue.py`, your review,
corrected catalogue to `corpus/notes/<file>.md` with the draft as `<file>.spark.md`, entry in
`sources.json`, copy into the corpus, `tools/corpus_sync.py`, `tools/census_by_origin.py`, then
MOVE the original to `~/projects/LIB_LLMOUT/Read/xtalk_py/toCorpus/`). You may add comments to
scripts that live only in the corpus. Whole stacks arrive as XTJSON harvests in
`~/projects/LIB_LLMIN/xtalk_py/fromXJSON/`: one file per stack, every object's script under a
banner naming the object; the harvest then moves to `LIB_LLMOUT/Read/xtalk_py/fromXJSON/`. The owner's goal: reuse scripts and workarounds, and turn
repeating requirements into `LIB_<Name>` projects.

## xTalk pitfalls already learned (from the owner's projects)

- Case-insensitive: a variable named `tExt` or `tHere` is the keyword `text` / `there`.
- A one-line `if c then x` directly before an `else` line takes that else.
- `does not begin with` is not xTalk: `not (x begins with y)`.
- An array element is either a value or an array; putting into `a[i]["k"]` replaces `a[i]`.
- Chunks nest small-inside-big only: `word 1 to -1 of char 1 to 5 of x` is a compile error, "bad chunk order".
